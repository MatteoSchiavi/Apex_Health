# Apple Health import

A user can import a manual Apple Health export from **Health app → profile → Export All Health Data**. The API accepts that ZIP at `POST /imports/apple-health`; the upload is limited to 100 MB, must contain exactly one `export.xml` (up to 500 MB uncompressed), and is parsed without extracting ZIP paths. The original ZIP is stored encrypted using the existing source-document path. Re-uploading the same file for the same account is idempotent.

The importer currently normalizes workouts, daily step counts, body mass, resting heart rate, oxygen saturation, sleep intervals, workout heart-rate summaries, daily heart-rate sample summaries, and Apple HRV SDNN summaries. It stores source/device, unit, and aggregation method with Apple values in `daily_biometrics.source_metrics`, including when another source has already filled a canonical field. Canonical daily fields are filled only when blank. For steps, the importer chooses one source per day (Apple Watch first, then iPhone, then source name) and counts overlapping intervals once; this avoids combining competing device totals. For sleep, stages take priority over generic asleep intervals, which take priority over in-bed intervals; overlapping time is counted once, and episodes separated by two hours are kept separate. SDNN is retained as `source_metrics.apple_health.hrv_sdnn_ms` and is deliberately not written to `hrv_readings`, whose other provider feeds can use RMSSD. Unknown HealthKit record types are ignored. Apple workout routes and per-sample heart-rate/power/cadence streams are not imported by this first version.

HealthKit is local to Apple devices. Apple does not provide a general server-side HealthKit OAuth/API endpoint, so this importer does not pull data automatically from a Watch or iPhone. A future native iOS companion would need explicit HealthKit permissions and a secure upload protocol; until then, users export and upload the ZIP themselves.
