# Small “System 1” models for Apex routing

Research updated 2026-10-05 after the user identified the TypeSafe Jev article and clarified Laya as the open alternative. This is a research note only: no weights were downloaded, no runtime was added, and no health decision behavior changed.

## Recommendation

Do not add a continuously running model service for this feature now. Apex only calls its free-tier classifier for accounts whose AI tier is `full`; `cheap_only` accounts already skip that request. Both paths retain the deterministic medical-intent marker check, and failures in the model classifier default to `lookup`. The classifier only chooses an answer tier; it does not analyze health values or authorize actions.

If the remote classification hop proves to be a meaningful latency or cost issue, benchmark a local typed classifier behind an optional adapter. For Apex’s English and Italian UI, **Laya multilingual is the most directly relevant first candidate to test**, because its published card describes a 322M-parameter, non-generative, typed decision model and lists Italian among 100+ languages. Jeff-Qwen3.5-0.8B is a credible newer English-only comparison with a documented CPU timing, but is larger and its card does not claim Italian evaluation. Neither has been evaluated on Apex’s routing labels; no benchmark winner can be named for this workload.

Start with the existing deterministic routing and remote classifier as baselines. Include a deterministic-only variant. If local inference does not improve held-out English and Italian routing accuracy, medical-intent recall, p95 latency, and cost while fitting the host budget, keep the current design. Do not use any of these models for clinical interpretation, workout recommendations, diagnoses, or approvals.

## Jev article and names

The user-specified article is [TypeSafe: Introducing System One Models and Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev). Direct requests to `typesafe.ai` were blocked by this environment’s HTTPS tunnel with `403 Forbidden`; no callable web-search tool is available. I could not verify the article’s precise parameter count, API contract, price, supported languages, or Jev’s deployment requirements from TypeSafe’s own page. The user has resolved what “Jev” means for this request, so this note does not treat unrelated repositories bearing that string as the TypeSafe product.

Hugging Face’s model API and cards were reachable. The card for [Laya](https://huggingface.co/convaiinnovations/laya) calls it a multilingual, non-autoregressive System 1 typed decision model and documents three checkpoints. Its multilingual checkpoint ([Laya multilingual](https://huggingface.co/convaiinnovations/laya-multilingual)) lists `mmBERT-base`, 322M parameters, 100+ languages including Italian, Apache-2.0, and 1,024-token default context. Hugging Face model metadata reports a 643,835,514-byte weight file (about 614 MiB); this is download size, not measured resident RAM. Its card describes fixed-choice, yes/no, and score outputs from one forward pass instead of generated prose. The canonical upstream model identity appears to fit the “Laya” clarification, but the blocked TypeSafe page prevents verifying that these are the exact same project/version being compared there.

Laya’s card reports its own benchmark results, including MASSIVE intent accuracy of 0.783 for its English checkpoint versus 0.657 for the multilingual checkpoint on English and 0.451 for the multilingual checkpoint averaged over 13 other languages. It reports XNLI accuracy of 0.731 over 14 non-English languages for the multilingual checkpoint. The card also reports 193–464 ms CPU latency for one query, depending on checkpoint/input. These are publisher-reported figures on public general-language benchmarks; they are not Jev-versus-Laya results under identical prompts, hardware, or tasks, and they do not establish Apex routing quality or its host RSS.

## Resource and integration constraints

The documented target is an 8 GB home server. In [`infra/docker-compose.yml`](../infra/docker-compose.yml), the API is capped at 1,024 MiB, Postgres/Timescale at 2,560 MiB, Celery worker at 1,536 MiB, and Redis at 256 MiB; the optional bot is 512 MiB. There is no model service, GPU allocation, or spare API memory reservation for inference. Weight-file size is only a lower bound: library, tokenizer, activations, allocator, concurrency, and precision affect resident memory. The CPU figures above come from different machines, so they do not predict Apex’s latency.

`backend/app/agent/routing.py` calls the free classifier only for `full` accounts after the marker prefilter; `_classify` sends the request text to the configured provider. A local classifier could remove that *extra classification request*, but the later coach call remains configured through `LLMClient` and may send the user request and personal context to a remote model. It therefore does not by itself make the chat private. The current language model adapter already provides a natural seam for an optional classifier, but a resident model in the API process risks exceeding its 1 GiB cap; a sidecar avoids coupling its memory to the API but consumes host memory and adds deployment/update work. Do not expose an unauthenticated model endpoint on the home network.

## Benchmark before deciding

Create a reviewed, held-out set of short English and Italian requests labelled `lookup`, `strategic`, and `medical`. Include code-switched messages, terse metric queries, paraphrased lab/symptom questions, spelling errors, negation, and ambiguous wording. Compare (1) current medical markers plus remote classifier, (2) deterministic-only routing, (3) Laya multilingual, and optionally (4) Jeff on English only. Test exact deployed checkpoints using the same examples and target CPU; report per-class precision/recall and confusion matrices, with medical false negatives separately reviewed, plus p50/p95 latency, cold start, peak RSS, concurrency behavior, failure/fallback rate, and network calls. Keep test rows disjoint from any fine-tuning data.

For a local candidate, return only one of the allowlisted labels and an optional confidence. Preserve the deterministic medical guard and disclaimer, validate every result, and use the existing safe fallback on failure. No classification result may become a clinical conclusion or trigger a plan change. If a candidate fails to improve measured p95 or classification quality enough to justify its resident memory and operational cost, leave the production architecture unchanged.
